## Purpose

让服务端内核的 Snell v4/v5/v6 TCP 出站以固定上游正式 CONNECT_V2 与双向零块结束语义，在一条承载上顺序处理多个独立目标业务流，减少不必要的新建连接，同时保证身份认证、旧数据隔离、并发租借互斥、有限资源及热替换和停机的真实回收。

## ADDED Requirements

### Requirement: 显式正式顺序复用

系统 SHALL 提供默认关闭的 TCP `reuse`，保持既有版本/记录模式/适用 obfs，启用后顺序请求可复用已完成的承载及记录状态；UDP MUST 仍独立建连，不私造并发流标识或报文。

#### Scenario: 顺序与并发目标

- **WHEN** 同一出站先后请求两个不同 TCP 目标，或并发打开多个业务流
- **THEN** 正常结束的顺序流复用同一承载而不重置 salt/nonce，后续目标重新验证标准首应答；并发业务不共用活跃逻辑流，目标之间无旧数据串流。

### Requirement: 回池前结束与失败关闭

系统 MUST 在已校验首应答、完成已接受写、发送一次零块及收到对端正式零块之后才将承载提供给下一业务；必要排空总时间不超过 30 秒、累计丢弃达到 0x80001 字节即关闭。错误身份/应答/AEAD、截断、写失败、未验证首应答及建连取消不能回池，不自动重放业务或回落 direct。

#### Scenario: 取消与旧数据排空

- **WHEN** 业务丢弃时仍有部分读写、旧响应或对端未发零块，或首应答/记录无效
- **THEN** 在有界排空完成前新流不能取用该承载，超限/超时/错误明确关闭，取消不重复请求/FIN，不把旧响应当作新目标数据。

### Requirement: 有界独立池与生命周期

系统 SHALL 按出站实例隔离最多 10 个空闲或等待排空的会话，空闲 180 秒过期，后台以 20 秒周期清理且取用时检查；热替换销毁旧池不误关活流，最终停机 MUST 取消并等待池持有的 socket/任务真实释放。

#### Scenario: 上限过期热替换与停机

- **WHEN** 池满、条目过期、配置移除旧出站或运行时强制停机
- **THEN** 多余/过期条目关闭，旧已交付流继续可用但不回失效池，停机不等待 180 秒空闲期限，端口与任务在期限内回收。

### Requirement: 原路径接线与证据边界

系统 MUST 在根出站及 TCP 链的 Snell 跳取池之后才决定是否按原链拨号，不静默忽略 reuse；开发结果必须与官方互通、平台、MSRV 和 release 验收分开记录。

#### Scenario: 链式及低层调用

- **WHEN** Snell 位于 SOCKS5 链前后，或无运行时连接工厂的低层 API 请求复用
- **THEN** 生产链不绕过上一跳，正常顺序业务真实减少承载拨号；不具备生命周期所有权的调用明确要求运行时工厂，不假称已经复用。
