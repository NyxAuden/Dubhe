## Context

提案创建时这是新项目，没有 Rust 实现、Cargo 工程或已运行测试。以下保留该阶段的设计依据；2026-11-04 第一阶段已实施，实际结果见 `docs/acceptance.md`，不再以本段描述当前运行状态。动机与本变更范围见 `proposal.md`，公开行为以四份 `specs/*/spec.md` 为准；长期覆盖不由本阶段的两个入口决定。

关键上游源码研究已经完成有界读取，具体路径和证据等级见 `docs/source-research.md`。Xray 的注册/Feature/Dispatcher、sing-box 的显式 registry 与 TCP/UDP 路由分工、Nowhere 的 Flow/Carrier/Egress 区分共同说明：可以统一运行基础，但不能将所有协议处理压成一个字节流适配器。

以下为建议的实施设计。用户已授权按阶段推进，不代表上游性能、安全性或客户端兼容性已经验证。当前 macOS 开发环境不等于目标 Linux 运行验收环境。

## Goals / Non-Goals

**Goals:**

- 一个可运行闭环验证模块注册、资源所有权、TCP/UDP、TLS、认证和真实客户端互通。
- 简单静态模块化，给后续协议留下明确边界而不提前定义无限扩展 ABI。
- 失败模式可观测、可取消、可测试；认证前限制与认证后转发分开。

**Non-Goals:**

- 不实现一个 Go 反射/全局 init 注册体系的 Rust 翻版。
- 不预先建立十几个空 crate、占位协议或通用事件总线。
- 不承诺通用 TLS stream 能实现所有 REALITY/Vision/QUIC 语义。
- 不把配置/API/分享链接兼容与线协议互通混为一项验收。

## Decisions

### 1. 单包、库与 CLI 分离，按职责划分内部模块

首阶段使用一个 Rust package，同时提供 lib 和 bin，暂定包名 `dubhe`。建议模块为 config、runtime、session、io、dns、route、outbound、protocol/socks5、protocol/trojan、tls、telemetry。测试独立于协议解析实现。

CLI 负责参数、信号与退出码；库负责构建服务、启动、请求停止和等待结束。初始命令为 `check -c <file>`、`run -c <file>`、`version`。不在库中安装全局信号处理器。

替代方案是立即拆分多 crate。当前没有第二个消费者或独立依赖边界，拆包先增加维护成本；当协议依赖或编译隔离有真实需要时再拆，保持内部依赖方向即可。

### 2. 原生 JSON 配置与显式构造器

根配置包含版本、入口列表、出站列表、路由及资源/日志设置。各协议使用有标签的配置类型，严格拒绝未知字段；不开放任意 Map 作为插件配置。原生格式与上游格式分开，不偷偷将上游同名字段赋予不同语义。

处理分为解析、静态/证书校验、构建计划、资源准备和运行。注册描述支持的网络能力与组合，未编译或未实现类型明确报错。首批使用显式 match/工厂表，必要时用 Cargo features 控制模块，不使用运行时动态库。

每个入口独立绑定明确地址。相同数值端口的 TCP/UDP 是否允许由实际 socket 能力决定，不将端口号本身作为全局唯一键。入口 tag、出站 tag 在各自命名空间内唯一。

### 3. 会话信息小而明确，流和包分开

公共会话信息仅含入口标识、可选用户标识、原始目标、源端点、TCP/UDP、必要的路由结果。密码/认证摘要不进入可 Debug 的公共会话。

TCP 使用支持半关闭的双向异步流。入口完成自己的认证和请求解析后向转发层提交目标与流；协议应答与拨号成功的先后由入口协调，例如 SOCKS5 成功应答不能在目标连接成功前发送。

UDP 使用明确的数据报与地址对象、关联生命周期和回程写入接口；不通过 AsyncRead/Write 假装它本来是流。域名到具体目标 IP 的解析结果与原始请求分开保留。未来 QUIC 连接持有多个业务流，协议模块管理流 ID 和帧格式，公共层仅管理预算与取消。

替代方案是单一万能 Transport/Session trait，缺点是将一切变成可选字段或丢失 UDP/QUIC 语义。当前只建立已被两个入口实际使用的小接口；未来反向出口和 QUIC 接口在对应变更中引入，不先写空实现。

### 4. 依赖与密码学边界

候选使用 Tokio/tokio-util、Serde/serde_json、bytes、成熟 SHA-224 与常量时间比较库、rustls/tokio-rustls、结构化日志库。普通 TLS 首选 rustls；不自行实现 TLS 或密码原语，不复制上游 Cargo 版本表。

TLS 加载用户提供的证书链与匹配私钥，首版没有 ACME 自动签发。测试使用独立本地 CA，参考客户端正常验证证书，不用 insecure 跳过证明兼容。

REALITY/Vision 后续会做单独可行性验证，允许调整 TLS 后端或引入经过审查的原生依赖；当前不定义虚假的万能 TLS provider trait。QUIC 库与拥塞控制在 P3 决定，不提前引入未使用的 Quinn 依赖。

项目源码暂按独立编写策略推进，不移植上游受许可约束的实现段落。具体项目许可证是首次对外分发前的门禁；任何代码复用都要先核查，不允许把这个问题拖到复制后处理。

### 5. 资源所有权和两阶段启动

先完整校验配置、准备证书与全部监听 socket，再释放接受连接的统一启动屏障。准备失败时通过所有权关闭已取得资源，不对外报告就绪。无需复制 sing-box 所有阶段或 Xray 的动态 feature 依赖系统。

运行器拥有任务集合与根取消信号。承载连接、UDP 关联和业务流各自持有 RAII 资源名额；将名额转交任务而不是立即释放。停机先停止 accept，再排空，最后取消和等待子任务，保证不遗留 detached 的流量处理任务。

握手预算按入口分隔，活动连接预算全局有界；认证失败不进入目标解析/拨号。TCP 复制缓冲固定且可估算；UDP 限制关联数、每关联目标映射、排队字节和空闲时间，队列满时丢弃新数据报并计数。日志也使用有界输出，不能通过错误日志量绕过资源限制。

### 6. DNS、路由和出站职责

首版路由按规格的首条匹配规则处理原始目标，不在 CIDR 匹配时隐式解析域名。Direct 才解析需要拨号的域名，Reject 不建立目标连接。配置必须显式提供默认出站。

DNS 首版采用异步 DNS 客户端读取系统 DNS 服务器配置，Linux 下以 resolver 配置和 hosts 映射为基线；不承诺完整系统 NSS/mDNS/企业名称服务行为。解析并发和请求期限有界，不在异步工作线程直接调用阻塞 getaddrinfo。DNS 查询通过底层网络完成，不再通过本次业务路由递归进入自身。

TCP 对解析得到的地址按稳定顺序尝试，在总拨号期限与每次尝试期限内完成；首版不宣称 Happy Eyeballs。UDP 每个已解析目标建立有界映射并校验回程来源；不会接受任意来源并转交客户端。域名解析使用的服务器超时不得拖住整个服务停机。

未来解析后 IP 规则、DNS 经代理、复杂选择器等将通过独立规格扩展，避免修改最小路由时静默改变既有语义。

### 7. SOCKS5 与 Trojan 的第一批行为

SOCKS5 对照 RFC 1928/1929；支持两种认证方式和 CONNECT/UDP ASSOCIATE，拒绝 BIND、丢弃 FRAG 非零的数据报。客户端端点以控制连接对端及请求中的合法地址信息校验；端口未知时只接受同一控制连接对端 IP 的首个合法包并固定端口，拒绝其他端点。控制连接生命周期决定关联生命期。

Trojan 使用 TLS + SHA-224 摘要认证；解析按字段逐段读，不假设 TCP 包或 TLS record 边界。CONNECT 的剩余数据交给 TCP 转发；UDP 流的每帧地址/长度单独解析，长度为载荷大端 u16，保留边界。对帧长先验证再分配，并限制累计缓冲。

首阶段不实现 Trojan fallback。认证失败或无效请求直接关闭，这是相对官方参考行为的公开差异，只声明有效客户端数据面的有限兼容。不返回自创的 Trojan 错误消息，不将此限制隐去。

### 8. 验收与支持声明

每个场景使用受控 TCP/UDP 目标、独立客户端或固定版本上游客户端。Trojan 验证 Mihomo、sing-box、Xray 客户端模式，不把族名当作所有变体的兼容证明。参考二进制仅用于测试，发布内核运行不依赖它们。

单元测试涵盖分段/合并头、长度、地址、未知命令和路由；集成测试涵盖真实转发、半关闭、UDP 多目标、超时、源校验、资源上限和启动/停机。资源测试以确定的连接数、队列预算和存活任务计数为主要断言，不仅观察 RSS 曲线。

Linux x86_64/ARM64 是建议的首批目标。需要分别记录构建、实际运行及长时间测试；本机 macOS 通过不能代表 Linux 通过。性能不预先许诺倍数，后续在相同条件、相同协议组合与固定硬件上比较。

## Risks / Trade-offs

- [首批协议少，容易误解为缩小目标] → 保留完整候选矩阵和阶段路线，P1 必须有真实客户端闭环，而非仅创建框架。
- [TLS 抽象不足以支持 REALITY/Vision] → P2 尽早验证真实需求，不对不透明 stream 接口作永久承诺。
- [UDP 内存或映射膨胀] → 队列、关联和目标映射分别有界，测试恶意长度和缓慢消费。
- [异步 DNS 与操作系统名称服务行为不同] → 明确首版系统配置 DNS 的边界，用受控解析器测试，完整 NSS 不属于首批兼容承诺。
- [上游文档快于固定 release 或包含报错 stub] → 每项记录证据等级、版本与角色；稳定 tag 和二进制 feature 必须单独核查。
- [Trojan 无 fallback 不等于完整上游替代] → 对外标明有限组合，不接收未实现选项，不宣称全部兼容。
- [源码参考引入许可争议] → 不复制实现段落，保留来源，复用前审查，首次分发前确定项目许可证。

## Migration Plan

新项目没有需要迁移的数据或现有运行服务。实施先在本机回环/隔离测试环境运行，再在自有 Linux 测试环境验收；本变更不自动部署到生产、不修改系统代理/防火墙/服务配置。

使用一个配置文件和独立进程运行，失败时退出并释放监听；回退是停止测试进程而非覆盖已运行的上游服务。后续版本涉及配置变化时再定义版本化迁移，不提前承诺所有上游格式兼容。

## Open Questions

以下事项不改变本变更的协议与行为契约：最终项目名；首次分发时的具体许可证（不复制上游代码是当前边界）；执行时可用的 Linux 测试宿主和参考客户端确切构建；经过依赖/MSRV 核查后的库版本。缺失运行环境的验收项必须标为未验证而不是降低规格。
