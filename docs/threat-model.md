# 威胁模型（2026-11-14）

本文是服务端内核的第一版威胁模型，用于指导测试、审计和部署，不构成安全审计结论。
范围限定为“服务端协议入口 + 本机管理面”，不覆盖客户端、TUN/透明代理、订阅、面板和
第三方上游实现本身。

## 1. 资产

- 协议凭据：VLESS UUID、VMess UUID、Trojan/Shadowsocks/Snell/Hysteria2/TUIC 密码或 PSK、
  WireGuard 私钥与 peer PSK。
- TLS/REALITY/ShadowTLS 私钥、证书链、REALITY 目标配置和短期票据密钥。
- 管理 API token、配置文件、systemd 环境/凭据文件。
- 业务载荷、目标地址、连接元数据、审计日志和统计数据。
- 主机网络能力：监听端口、出站连接、DNS 查询、UDP 套接字和文件描述符。

## 2. 信任边界

| 边界 | 一侧 | 另一侧 | 说明 |
|---|---|---|---|
| 公网/客户端 | 任意客户端 | 协议握手与数据面 | 未认证流量可到达监听器 |
| 上游代理/DNS | 本内核 | 上游服务或 DNS 服务器 | 返回数据不可信，可能畸形或延迟 |
| 本机管理面 | 运维/本机进程 | `/healthz`、`/stats`、`/metrics`、`/connections` | 回环 + Bearer token |
| 配置文件 | 配置作者/部署者 | 进程 | 配置可决定监听、路由、证书和出站 |
| 本地代码/依赖 | 本仓库 + vendored 代码 | 进程 | 依赖公告和补丁需要持续审查 |
| 主机 | 操作系统/内核 | 进程 | 假定主机和内核未被攻陷 |

## 3. 主要威胁与现有控制

| ID | 威胁 | 影响 | 现有控制 | 仍需验证/缺口 |
|---|---|---|---|---|
| T1 | 未认证握手/连接耗尽 | CPU、内存、FD 耗尽 | 每入口 `max_handshakes`、全局 `max_connections`、握手/拨号/DNS 超时、有界任务 | 没有按源 IP 的令牌桶/失败退避；需实际握手风暴压测 |
| T2 | 慢客户端/半包 | 任务和缓冲区长期占用 | 首包/握手/读超时、有界缓冲 | 需逐协议验证超时和取消路径 |
| T3 | 畸形长度、截断、重放 | panic、越界、状态污染 | Rust 安全边界、长度前置校验、VMess/Shadowsocks/REALITY 重放池、失败关闭 | 无连续模糊测试；需 ASan/差分测试 |
| T4 | UDP 放大/反射 | 被用于对第三方反射流量 | 每关联目标数、队列字节/包上限、丢弃计数 | 没有源地址验证或响应/请求比例限制；UDP 入口不应暴露给不可信网络 |
| T5 | 认证绕过/降级 | 未授权代理访问 | 协议凭据、TLS/REALITY、失败关闭、SOCKS5 无认证非回环默认拒绝 | 需官方客户端负向矩阵和独立审计 |
| T6 | 凭据/私钥泄漏 | 完全接管入口 | 日志脱敏、ProxyOutbound Debug 脱敏、token 文件 0600 检查、TLS 私钥拒绝组/其他用户可读 | 配置文件权限未统一检查；内存中的密钥未做零化审计 |
| T7 | 管理 API token 泄漏 | 查看目标地址/关闭连接 | 仅回环监听、Bearer 定长比较、token 不写日志 | 本地同用户进程可读配置/环境；没有 token 轮换 API |
| T8 | SSRF/开放代理 | 访问内网或第三方目标 | 路由规则、fallback 目标由配置决定 | 默认 direct 不限制目标；生产必须用出站防火墙/网络策略隔离 |
| T9 | DNS 投毒/重绑定 | 连接到攻击者地址 | 可配置 DoT/DoH、显式 CA、hosts 优先 | 明文 UDP DNS 仍可被篡改；需部署 DoT/DoH 和网络策略 |
| T10 | QUIC/TUIC 0-RTT 重放 | 早期请求被重复执行 | TUIC 0-RTT 默认关闭；WireGuard 有重放保护 | 开启 0-RTT 的协议需确认业务幂等/抗重放边界 |
| T11 | HTTP/2/gRPC/XHTTP 头部/流耗尽 | 内存/CPU 压力 | 头部大小限制、会话 TTL/上限、流上限、有界队列 | 需逐版本验证与官方客户端交互下的上限 |
| T12 | fallback 目标滥用 | 访问非预期本地服务 | 目标只来自配置，不来自客户端；Unix socket 支持 | 配置作者可指向任意本地服务；需最小权限和网络隔离 |
| T13 | 依赖漏洞/供应链 | 远程执行或信息泄漏 | `cargo-deny`、固定 Cargo.lock、vendored 补丁记录、许可证门禁 | 尚无持续公告扫描之外的 fuzz/审计；构建工具本身需可信 |
| T14 | 日志注入/敏感信息 | 伪造日志或泄漏目标 | JSON 日志、错误限速、默认不记录目标和载荷 | 管理 API 连接列表含目标；日志采集端需访问控制 |
| T15 | 主机权限过大 | 提权/横向移动 | systemd unit 非 root、清空 capability、文件系统/系统调用限制 | 未在目标发行版实测；绑定特权端口时需单独授权 |

## 4. 已知高风险部署约束

- 不要把 SOCKS5 无认证、HTTP/Mixed 或任何未认证入口暴露到公网。
- UDP 入口没有通用反射防护；公网部署应限制来源、关闭不必要 UDP 协议，或用前置防火墙。
- 默认 `direct` 出站可以访问进程可达的任意目标；生产必须用网络命名空间、防火墙或
  上游 ACL 限制内网访问。
- 明文 DNS 不能抵抗路径上的投毒；生产应使用 DoT/DoH，并固定 CA 和网络路径。
- 管理 API 只能回环监听；不要通过端口转发把它暴露到公网。
- 证书、私钥、token、配置文件应只允许运行用户读取；当前只有 token 文件有启动权限检查，
  其他文件需要在部署层保证。

## 5. 安全假设与非目标

假定：
- 操作系统、内核、Rust 工具链和 crates.io 依赖未被攻陷。
- 配置作者是可信的，配置可以决定监听、路由和上游。
- 协议凭据通过安全渠道分发，客户端设备未被攻陷。

非目标：
- 不防御已获得主机 root/同用户权限的攻击者。
- 不提供客户端匿名性、流量伪装保证或抗审查保证。
- 不替代独立安全审计、渗透测试、模糊测试和合规评估。

## 6. 后续验证计划

1. 对每个协议入口做畸形长度、截断、重放、并发上限、取消/停机测试，并记录失败关闭证据。
2. 建立 cargo-fuzz 目标，至少覆盖 VMess AEAD、VLESS/Encryption、Shadowsocks、Trojan、
   REALITY、XHTTP、gRPC framing、mKCP、TUIC、WireGuard、Snell、ShadowTLS。
   当前 `fuzz/` 已有配置、Vision、SOCKS5 数据报、地址、XUDP、VLESS/Trojan 数据报目标；
   2026-11-14 已对 15 个入口各运行 30 秒，0 crash/OOM。该结果不等于完整握手 fuzz，
   边界见 [fuzz 记录](fuzzing.md)。
3. 在 Linux x86_64 原生环境执行握手风暴、慢客户端、UDP 包速率和 72 小时 soak。
4. 独立第三方审计前，先完成威胁模型评审、依赖公告清零和发布产物签名。
5. 每次新增协议/传输时更新本表，不能只增加功能不增加威胁条目。
