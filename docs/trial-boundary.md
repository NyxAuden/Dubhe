# 0.1.0 受控试用边界（待验收）

唯一拟交付组合：Debian 11 x86_64，解包后的 `linux-x86_64-musl`，专用非 root 用户，单租户私有回环环境。固定 Xray v26.10.31 客户端 → Trojan/TLS 原生 TCP → 一个受控 TCP 回显或 HTTP 目标。完成下列验收前只作候选，不承诺线上容量或长期运行。

1. **准备配置**：从 `examples/trojan.json` 取 TLS 入口，替换示例凭据和证书路径；客户端验证服务端名称和 CA。保留回环监听。将默认路由从 `direct` 改为 `reject`，只为 `trojan-tls`、`tcp`、确切目标 IP 与端口添加 direct 规则。独立出口策略也只放行该目的地。API 如启用，只监听回环、使用独立 token_file；秘密不归档。执行 `"$BIN" check -c "$CFG"`，再用同一用户 `"$BIN" run -c "$CFG"`。这里 `BIN` 为已核验的绝对路径，`CFG` 为受控配置。
2. **本轮不开放**：公网、多租户、其他平台、UDP 转发、NW3 全部角色、reverse/Mux、detour、fallback、其他协议及承载。平台包能构建不等于已获试用批准。Trojan 固定凭据可在新 TLS 会话复用，不提供应用层一次性口令语义。
3. **已知失败**：原三客户端 79 项为 51 通过、12 预期不支持、16 失败（sing-box 1、mihomo 15）。失败未修复或豁免；原始分类见 [fail-closed 矩阵](fail-closed-matrix.md)。旧 ELF `4641055b…` 的 7/7 仅是该 ELF 的 SOCKS5 回环记录。
4. **放行前**：记录 run ID、源码 SHA、包和 ELF SHA、UID、配置模板、客户端版本。对实际包先跑 `bash tools/release-smoke.sh "$BIN"`，再用上述真实组合分别验证允许、错密钥、被禁目标；后两者在监听已 ready 的目标侧均不得出现连接。证据还须包含进程外拒绝、两小时排空曲线、SIGTERM 和恢复后重复探针的结果。任一缺失不得宣布部署已验收。
5. **回切目标**：升级前由操作者填写上一套已验服务的二进制绝对路径及 SHA、匹配配置及校验值、服务名、客户端连接设置和成功探针；任一为空不接管已有服务。异常时停止候选，恢复整套旧程序/配置和客户端指向，以原探针验证允许和拒绝。首次空机隔离部署的回切目标是“停止试用、恢复无监听”，用 `ss -lntup` 核对端口；它不等于恢复生产服务。旧 `4641055b…` 不自动充当回切目标。

### 一组可核验的部署参数

在受控环境中可将 `examples/trojan.json` 的 `route` 替换为下列对象；`127.0.0.2:35201` 必须是操作者自己的测试目标。其余字段按第 1 项填写，不可沿用示例密码。

```json
{"default":"reject","rules":[{"inbounds":["trojan-tls"],"networks":["tcp"],"ip_cidrs":["127.0.0.2/32"],"ports":[{"start":35201,"end":35201}],"outbound":"direct"}]}
```

例如使用返回固定已知内容的本机 HTTP 服务作为目标：先在目标端确认允许和禁止的监听器均 ready。使用固定版本 Xray 的已校验配置（本地 SOCKS5 入口 `127.0.0.1:1080`，唯一出站为上述 Trojan 入站，无备用直连）启动 `xray run -c "$XRAY_CFG"`，然后执行：

```sh
curl --fail --max-time 5 --noproxy '' --socks5-hostname 127.0.0.1:1080 http://127.0.0.2:35201/probe
curl --fail --max-time 5 --noproxy '' --socks5-hostname 127.0.0.1:1080 http://127.0.0.3:35201/probe
```

第一条必须返回预置内容；第二条必须失败且禁止目标的 `accept` 计数不增加。将 Xray 配置换成仅密码不同的副本后重复第一条，同样要求失败且允许目标无新增连接。区分客户端路由、内核拒绝、外层出口策略三项结果；仅凭 curl 非零不能证明原因。回切后用旧服务原有客户端配置重复探针。不要为了在现有主机满足前置条件而直接修改系统防火墙。
